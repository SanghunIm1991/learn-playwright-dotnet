## 2. プロジェクト概要

本プロジェクト（LearnPlaywright）は、Playwrightを用いたブラウザアプリのテスト自動化を学習することを目的とした学習用プロジェクトである。学習の題材として、テキストボックス・スライダー・プルダウンリスト・ラジオボタン等の一般的なUIコンポーネントを持つユーザー情報入力フォームのサンプルサイトを新規に構築し、そのサイトに対してPlaywright for .NET（C#、NUnitベース）によるテストコードを書きながら、テスト自動化の作法を実践的に習得する。

本プロジェクトは通常のアプリケーション開発とは異なり、「動くサンプルサイトとテストコード」に加えて、初心者がPlaywrightによるテスト自動化を段階的に学べる学習教材（ベストプラクティス解説および段階的な学習コンテンツ）そのものを成果物として含む点に特徴がある。成果物は最終的にGitHub上のPublicリポジトリとして公開し、ソースコード・ドキュメントを第三者が参照できる状態にする。

## 3. 機能要件

### 3.1 サンプルサイトの機能（UI・保存/読込・Cookieによるユーザー識別）

| ID | 要件内容 |
|---|---|
| REQ-01 | サンプルサイトのフォーム画面は、テキストボックス、スライダー、プルダウンリスト、ラジオボタン、送信ボタン、読み込みボタンの6種類のUIコントロールを表示できる。 |
| REQ-02 | 利用者が送信ボタンを押下すると、フロントエンドは各UIコントロールの入力値をJSON形式のデータとしてサーバーへPOST送信できる。 |
| REQ-03 | サーバーは、リクエストに含まれるユーザー識別用Cookieの値に対応付けて、POST送信された入力値をJSONファイルとしてサーバー側のファイルシステムに保存できる。 |
| REQ-04 | 利用者が読み込みボタンを押下すると、フロントエンドはサーバーへGETリクエストを送信し、リクエストに含まれるユーザー識別用Cookieの値に対応するJSONファイルの内容を取得できる。 |
| REQ-05 | フロントエンドは、読み込みボタン押下で取得したJSONの内容に基づき、各UIコントロール（テキストボックスの文字列、スライダーの位置、プルダウンリストの選択項目、ラジオボタンの選択項目）の値を画面上に復元できる。 |
| REQ-06 | サーバーは、リクエストにユーザー識別用Cookieが含まれていない場合、新規にユーザー識別用Cookieを発行し、レスポンスに付与できる。 |

### 3.2 テスト自動化に関する機能

| ID | 要件内容 |
|---|---|
| REQ-07 | テストコードは、NUnitの`TestCaseSource`等の仕組みを用いて、パラメータ化されたテストケース（同一のテストロジックに対して複数の入力値・期待値の組を適用するテスト）を定義できる。 |
| REQ-08 | テストコードは、入力値と期待値の組をレコード型等のデータ構造として一元管理し、個々のテストメソッド内に入力値・期待値を直接記述（ハードコード）せずに済む構成を提供する。 |
| REQ-09 | テストコードは、「UIへの入力操作→送信ボタン押下→サーバー保存内容の検証」、および「読み込みボタン押下→UI復元後の各コントロール表示内容の検証」という一連のシナリオを、Playwrightにより自動実行できる。 |

### 3.3 学習教材としての機能

| ID | 要件内容 |
|---|---|
| REQ-10 | 成果物ドキュメントは、Playwrightを用いたテスト自動化のベストプラクティス（テストケースの独立性、待機処理の書き方、ロケーターの選び方、テストケースのパラメータ化の考え方等）を解説する章を含む。 |
| REQ-11 | 学習教材ドキュメントの構成は、REQ-10のベストプラクティス解説章を先に配置し、その後にREQ-12の段階的学習コンテンツを配置する順序とする。 |
| REQ-12 | 成果物ドキュメントは、初心者が段階を踏んで学習できるよう複数のステップ（レッスン単位）に分割された学習コンテンツを含み、各ステップは解説テキストと、そのステップに対応するサンプルコードの両方を含む。 |

## 4. 非機能要件

### 4.1 セキュリティ

| ID | 要件内容 |
|---|---|
| NFR-01 | 認証・認可機構を持たない本システム（CON-05参照）の入力データがJSONファイルとして保存されGitHubリポジトリにも取り込まれ得ることを踏まえ、利用者が学習目的のダミー値のみを入力し、氏名・連絡先・クレジットカード番号等の実在の個人情報・機微情報を入力しないよう、UI上の表示（ラベル・注意書き等）またはドキュメント上で明示すること。 |
| NFR-02 | サーバーは既定の設定でローカルホスト（localhost / 127.0.0.1）のみで待ち受け、外部ネットワークインターフェースからの接続を前提としない構成であること。 |

### 4.2 学習容易性

| ID | 要件内容 |
|---|---|
| NFR-03 | 学習教材は、Playwright未経験の初心者がドキュメントを先頭から順に読み進めるだけで、環境構築からサンプルテストの実行までを到達できる分かりやすさを備えること。 |
| NFR-04 | 段階的学習コンテンツの各ステップは、それより前のステップの内容のみを前提知識とし、後続のステップで説明する内容を前提としない構成であること。 |
| NFR-05 | 学習教材中のサンプルコードには、初心者の理解を助けるための説明コメントを付与すること。 |

### 4.3 保守性

| ID | 要件内容 |
|---|---|
| NFR-06 | サーバー側の実装は、入力値の検証・JSON変換・復元処理等のロジック層と、HTTP通信処理を分離し、ロジック層が外部ライブラリに依存せず単体テスト可能な構成であること。 |
| NFR-07 | テストコードは、入力値・期待値のデータをテスト実行ロジックから分離した構成とし、新しい入力パターンを追加する際に既存のテストロジック本体の修正を必要としない構成であること。 |

### 4.4 見た目・視認性

GUIを持つ題材であるため、配色・視認性に関わる非機能要件の要否を検討した。本プロジェクトの主眼はPlaywrightによるテスト自動化技法の習得であり、UI/UXデザインの高度化そのものは目的ではない。一方で、サンプルサイトは学習者が実際に目視・操作する画面であるため、最低限の可読性は確保する必要があると判断し、以下を非機能要件として定める。

| ID | 要件内容 |
|---|---|
| NFR-08 | フォーム画面の文字色と背景色の組み合わせは、コントラスト比4.5:1以上（WCAG 2.1レベルAAの通常テキスト基準値を可読性確保の目安として採用する）を満たすこと。 |

なお、NFR-08はコントラスト比の数値目安のみを可読性確保の目的で採用するものであり、WCAG等の公式アクセシビリティガイドラインへの全面準拠（スクリーンリーダー対応、キーボード操作のみでの全操作対応等を含む）、多言語対応、レスポンシブ（モバイル画面）対応までは求めない。これらは本プロジェクトの目的（テスト自動化技法の学習）を超える高度なUI/UXデザイン要件であるため、非機能要件の対象外とする（詳細は「6. スコープ外」を参照）。

## 5. 制約

| ID | 制約内容 |
|---|---|
| CON-01 | 対応OSはWindows 11とし、ローカル環境での実行のみを前提とする。クラウド環境・外部サーバーへの本番デプロイは行わない。 |
| CON-02 | フロントエンドはHTML、CSS、JavaScriptを用いて実装し、React・Vue等のフロントエンドフレームワークは使用しない。 |
| CON-03 | バックエンドはC#および.NET 10を用いて実装する。ASP.NET Coreを用いることを想定するが、具体的な構成はコンポーネント設計工程で確定する。 |
| CON-04 | テストコードはPlaywright for .NET（C#、NUnitベース）を用いて実装する。 |
| CON-05 | 本システムは学習用サンプルであり、認証・認可機構を実装しない。 |
| CON-06 | 成果物（ソースコード・ドキュメント）は、最終的にGitHub上のPublicリポジトリとして公開する。 |
| CON-07 | GitHubへの公開に際し、ソースコード・ドキュメント本文、およびコミット履歴のメタデータ（コミット作成者名・メールアドレス等）に、個人情報・秘密情報（APIキー、パスワード、接続文字列等）を含めないこと。 |

## 6. スコープ外

以下の事項は、本プロジェクトの目的（Playwrightによるテスト自動化の学習）の範囲外として、今回は明示的に扱わない。

- 本番運用環境（クラウド・外部サーバー等）への実際のデプロイ、および本番運用を前提とした構成（CON-01、CON-05参照）
- 複数ユーザーの同時アクセスを想定した性能要件・負荷対策
- 認証・認可機構の実装（CON-05参照）
- HTTPS化・TLS証明書対応（ローカルHTTPでの実行のみを前提とする）
- WCAG等の公式アクセシビリティガイドラインへの準拠、多言語対応、レスポンシブ（モバイル画面）対応（4.4節参照）
- JSONファイル以外の永続化手段（RDB等のデータベース導入）
- CI/CDパイプライン（GitHub Actions等による自動テスト実行基盤）の構築。将来的な検討事項とし、本要件定義の対象外とする。
